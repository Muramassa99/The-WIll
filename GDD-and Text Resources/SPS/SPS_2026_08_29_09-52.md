## Authoritative Handle Coordinate Contract

- Saved/runtime primary and support Handle positions use one physical coordinate:
  normalized `0..1`, Pommel to Tip.
- Directional UI displays `0..1` directly.
- Balanced UI may display `-1..1`, but it is only a presentation/input lens:
  `-1 -> 0`, `0 -> 0.5`, `+1 -> 1`.
- Intrinsic, weapon-derived COM selects the display mode. Active grip-derived
  handling values must never switch that mode.
- Primary and support hands live on the same Handle segment and use the same
  coordinate mapping. No hidden support base, midpoint reinterpretation, or
  negative directional travel remains.
- `axial_reposition_offset` remains its separate existing weapon-reposition
  control and was not folded into this migration.

## Implemented

- Motion nodes now carry an explicit Handle-coordinate schema marker.
- Station schema advanced from 3 to 4 without re-running the old destructive
  skill-draft reset.
- The exported station default intentionally remains 3 because real version-3
  `.tres` saves omitted the then-default-valued property. Normalization detects
  that omitted value, marks existing motion nodes as legacy, and stamps 4.
- Profile-aware WIP loading migrates legacy authored UI values into canonical
  `0..1` coordinates before editor or runtime consumption.
- Migration invalidates derived retarget snapshots and baked runtime clips so
  old coordinate semantics cannot overwrite the canonical authored values.
- Public Skill Crafter setters now accept canonical values only. UI callbacks
  perform display-lens conversion at the boundary.
- Primary and support preview paths consume the same canonical resolver.
- Runtime clip schema advanced so incompatible cached clips are not reused.
- Older verifiers were updated to stop injecting the removed signed/base-relative
  contract.

## Deliberate Legacy Decision

Legacy signed values are interpreted as the values authored in the old Skill
Crafter controls and converted through the correct directional/balanced UI lens.
The migration deliberately does **not** preserve the old hidden per-hand-base
runtime displacement, because that was the broken path that produced negative
directional coordinates and support-hand time-travel behavior. Consequently, an
old support seat can move to the physically intended canonical Handle location.
