## Done Since Last SPS

### Handle authoring modes

- The Handle menu now exposes three authoring paths:
  - `3 Point Spline`
  - `3 Point Linear`
  - `2 Point Linear`
- Generated geometry and the editable guide use the same selected trajectory.
- Three-to-two preserves endpoints and discards the middle point.
- Two-to-three inserts a new approximate midpoint.
- Three-to-three retains all three authored points while changing interpolation.
- Existing single-Handle replacement/edit behavior remains intact.

### Semantic action history

- Added a reusable generic action-history container. Its default capacity `0`
  means unbounded by action count; Forge owns the domain-specific prune policy.
- Added compact per-point spline append/move records so retained history does
  not copy the entire growing path for every dot.
- Generate is one structural action. Undo returns to editable point placement;
  Redo restores the generated body.
- A completed freehand brush stroke remains one action regardless of sample
  count.
- Successful native promotion acknowledgement validates the transition revision
  and promoted layer ID, then removes only the action prefix through that CSG.
- Save/Save As do not clear the active action journal.
- New/Open clear it. Closing and re-entering Forge in the same live controller
  session preserves it.
- A new authored action after Undo abandons both action Redo and corresponding
  native layer Redo.

### Held input

- Default bindings remain `Ctrl+Z` and `Ctrl+Y`.
- Undo/Redo are exposed to Forge V2 keybinding configuration; Mouse 4/Mouse 5
  are valid bindings.
- A hold performs one immediate action, waits `0.38 s`, repeats from `0.14 s`,
  accelerates by `0.82`, and bottoms out at a `0.035 s` interval.
- Release stops before another repeat. The same termination applies to primary
  key release, modifier-first release, Mouse 4/5 release, focus loss, popup or
  dialog ownership, keybinding capture, Save, and Forge close.
- Every Undo performed in one hold is sealed on release as one Redo batch.
- Batched Redo publishes each structural CSG/Handle transition before advancing
  to the next one, preventing logical history from outrunning native history.
- The hot UI status summary is constant-time; full chronological label lists
  remain explicit diagnostic calls rather than being rebuilt on each refresh.
