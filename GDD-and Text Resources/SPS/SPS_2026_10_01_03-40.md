## Done Since Last SPS

Added `native/grip_contact/src/grip_saved_contact_kernel.{h,cpp}` and
`grip_ordered_target.{h,cpp}`. `GripSavedContactKernel` owns complete ordered
target preparation, material/digit/palm query grouping, numerical calls,
contact witness normalization and safety aggregation. The original numerical
`GripContactKernel` is reused directly in C++, with `release_target` added.
Registered the class and rebuilt the existing standalone extension using only
the workspace compiler, CMake and pinned godot-cpp bindings. No installations,
outside applications, Forge changes or fast-math settings.

`saved_wrapper_skin_contact.gd` now defaults to the complete batch. The original
script and per-segment C++ adapter remain selectable references; only one runs
normally. Configuration must happen before acquisition. Each instance owns
bounded prepared/native caches (64 entries each, at most 192 typed targets).
Hashes filter candidates; exact type/component-bit/order comparisons decide
reuse against detached snapshots. Reset/eviction release handles. The batch
bypasses the old serialized segment-result cache, intentionally changing actual
work/cache counters while retaining logical results.

The runner supports `THE_WILL_GRIP_CONTACT_BATCH=0|1` along with existing
contact/section backends. It rejects explicit GDScript plus batch 1. New
`saved_contact.native_batch` chronology records expose the complete boundary.
The README and `tools/grip_plane_proof/GRIP_CHRONOLOGY.md` document the contracts,
commands, timing scopes and original reference route.

Review caught two native port defects before final verification: signed-zero
bounds required Godot's MIN/MAX tie semantics; empty container script metadata
was a null Object that disabled every cache hit. Container schemas now use
`is_same_typed`; actual geometric data still compares exactly. The new verifier
also needed a runtime IEEE-754 negative-zero fixture because the script literal
lost its sign. Final assertions test real signed-zero inputs.
