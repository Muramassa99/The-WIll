# Forge V2 Action Undo/Redo Work Scope - 2026-08-30

## Outcome

Forge V2 Undo and Redo operate on the latest chronological **user action**, not
on the latest committed material layer.

- `Ctrl+Z`: default Undo binding.
- `Ctrl+Y`: default Redo binding.
- Both actions are exposed in the Forge V2 keybinding menu and may be rebound to
  keyboard or mouse input, including Mouse 4 and Mouse 5.
- User actions have no independent numeric cap.
- The native material structure remains `checkpoint + five ordinary tail CSGs
  + protected Handle`. The five-body tail is unchanged.
- User actions age out only when their owning oldest ordinary CSG is
  successfully consolidated into the native checkpoint.
- A new authored action after Undo permanently abandons the Redo branch.
- One pointer drag is one action, regardless of its motion-sample count.
- Save and Save As finalize pending work but are not creative actions and do not
  divide or clear the live-session journal.

This is an editor contract layered over the existing bounded native material
history. Native body count is bounded for performance; user-action granularity
inside that structural window is not flattened to five clicks.

## Structural History Versus Action History

### Native material structure - frozen

The proven `1 + 5 + Handle` design remains unchanged:

- old committed ordinary material is accumulated into one checkpoint;
- the five latest ordinary material operations remain native-reversible;
- the protected Handle remains outside that ordinary tail;
- the live native/CSG body count stays bounded;
- no native capacity constant is changed by this task.

### User action journal

The Stage Controller owns an unbounded-by-count chronological journal of compact
semantic actions. The Forge controller, not the generic history container,
owns the CSG/checkpoint pruning policy.

The journal is divided naturally into CSG authoring epochs:

- a 5,000-sample freehand stroke is one action and one structural CSG;
- a 5,000-dot spline is 5,000 point actions plus Generate, while still becoming
  one structural CSG;
- every point action in that spline remains reversible while its generated CSG
  belongs to the active five-CSG tail;
- after successful native promotion acknowledgement, the promoted CSG action
  and every earlier action are discarded as one chronological prefix;
- a rejected, deferred, timed-out, or rolled-back promotion does not move the
  action-history floor.

Compact records must not duplicate the complete WIP, checkpoint mesh, ledger,
or full path for every dot. Point append/move records use reversible sequence
splices. A generated CSG may retain one complete source-path/document snapshot;
that full snapshot is structurally bounded by the native tail.

Undo peeks at a record, applies its inverse, and confirms history movement only
after replay succeeds. Redo follows the same rule. Failed replay leaves history
in place.

## Atomic Action Boundaries

- One freehand press-to-release stroke is one action.
- One primitive placement click is one action, even if it creates several
  internal operands.
- One spline/Handle point placement is one action.
- In point-placement mode, repeated Undo removes points newest-to-oldest,
  including the first point, without leaving the selected tool.
- One spline/Handle/profile control-point press-to-release drag is one action.
- Finish Path and Cancel Path are actions when they change authored state.
- Generate plus structural Commit remain one creative action. Commit is not a
  second Undo step.
- Undoing a generated line body returns to its exact editable path. Further Undo
  walks backward through its individual point placements.
- Clear Pending Work and Delete Selected Pending Body are actions.
- Tool, material, camera, grid, current selection, and keybinding choices are not
  document actions unless a later explicit contract changes that rule.

## Held Undo/Redo Input

- A press performs one immediate step.
- A short deliberate delay follows.
- Continued hold repeats slowly, then accelerates toward a bounded fast repeat,
  like held Backspace in a text editor.
- Release stops immediately. No operation may continue after physical input
  ends.
- Focus loss, opening a blocking dialog, beginning keybinding capture, rebinding,
  Save, or closing Forge cancels the active hold immediately.
- Keyboard and Mouse 4/Mouse 5 use the same repeat behavior.
- One held Undo gesture becomes one Redo batch after release. One Redo restores
  everything removed by that single hold. The restored actions remain
  individually undoable afterward.
- Repeat timing is generated by Forge rather than operating-system keyboard
  echo, so keyboard and mouse behavior are deterministic.

## Handle Transaction

The Handle remains one unique protected component.

- Entering Change Handle exposes its saved path/profile without leaving the old
  CSG in the way.
- Local edits can be undone while Change Handle is open.
- Applying/committing replacement collapses that local session into one global
  atomic Handle swap.
- Undo restores the preceding Handle; Redo restores the replacement.
- Cancel restores the original without a completed replacement action.
- Save/Save As while Change Handle is open applies, validates, commits, then
  saves under the existing Save contract.

## Lifecycle And Async Rules

- Save/Save As preserve the live session journal across their internal reload.
- Explicit New Draft and explicit Open/Load reset the journal.
- Closing Forge does not reset history. Returning to the same still-loaded
  workspace resumes it.
- History does not persist across application shutdown or a later explicit
  project open.
- Permanently deleting the open WIP resets its journal.
- Undo/Redo are unavailable during placement, deferred commit, or pending native
  promotion acknowledgement.
- Stable body/layer IDs and compact copied values are authoritative; replay does
  not depend on live positional guesses.
- Abandoning Redo also discards corresponding native undone layers/bodies.

## Acceptance Checks

- More than five point actions remain reversible before any CSG checkpoint
  promotion.
- Six generated CSGs produce checkpoint CSG 1 plus active tail CSGs 2-6. Undo
  may traverse Generate/dots for CSGs 6 through 2 and stops at consolidated CSG
  1. Redo restores that chronology.
- A 5,000-dot path stores compact per-dot deltas rather than complete path copies.
- A new action after partial Undo clears both action and native Redo branches.
- Three-to-two Handle mode Undo restores the discarded middle point exactly.
- Save preserves history; explicit Load/New clears it.
- Held Undo accelerates, stops on release, and is restored by one Redo batch.
- Primary-key release, modifier-first release, Mouse 4/5 release, application
  focus loss, popup ownership, and Forge close all terminate the held gesture
  before another repeat can run.
- One Redo after a held Undo spanning two committed CSGs advances both the
  logical layer stack and native Boolean-history cursor by two states.
- UI availability remains truthful in Handle-only, checkpoint-only, pending,
  and async-blocked states.
- Mouse 4/Mouse 5 work through the covered Forge GUI surface.
- No unbounded native-body, checkpoint, full-WIP, or full-ledger duplication is
  introduced.
